# Stage 00 — Intake / Choose

One job: decide what reality says before implementation starts.

## Inputs

- User request and available source material.
- Existing repository, deployment, customer, market, and commercial evidence when available.
- Layer 3: `../../_config/mission.md`.
- Layer 3: `../../shared/VIBE_DECISION_STANDARD.md`.
- Layer 3: `../../references/SOURCE_PROVENANCE.md`.

Do NOT load later stage outputs or implementation details that are not part of the current baseline.

## Process

1. Record the current baseline without changing product code.
2. Classify the work: `SELL`, `USE`, `MERGE`, `PARK`, or `ARCHIVE`; record greenfield or brownfield mode.
3. Write OUTCOME, TARGET, CONSTRAINTS, PROOF, COMMERCIAL VALUE, rollback point, and the Intent → Standard → Evidence contract.
4. When a product/market idea is materially unproven, separate the durable human instinct from the first product shape. Research audience-matched analogs, proven mechanics, failed attempts, and what is still genuinely new. Treat new load-bearing elements as hypotheses requiring the smallest useful test.
5. Record third-party methods, media, code, data, or references that may affect rights, attribution, or later distribution. Mark missing evidence `UNVERIFIED` instead of guessing.

## Outputs

- `project-contract.md` -> `output/`
- `baseline.md` -> `output/`
- `validation-map.md` -> `output/`
- `source-provenance.md` -> `output/`
- `plain-language-summary.md` -> `output/`

## Human gate

The human confirms the actual outcome, audience, constraints, commercial reason, and what would count as proof. A PARK or ARCHIVE classification stops the build path.

## Plain-language proof

Explain the project like a job ticket: what is real now, who it affects, what must stay safe, what is proven already, what is still a bet, and how we will know the work helped.
