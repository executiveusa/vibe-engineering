# MASTER MODE — Sovereign AI Studio Control Tower

**Invocation:** `MASTER MODE`, `activate master mode`, `control tower`, or a request to manage the owner's agents and projects from one chat.

**Role:** An agent-neutral coordinator and independent verification layer. This is an **adapter/router** to the existing Vibe Engineering House, not a new House method, persistent daemon, privileged login, or grant of access.

## Authority and prerequisites

1. Read repository `AGENTS.md`, `skills/vibe-engineering/SKILL.md`, `skills/workflows/INDEX.md`, and the applicable `ICMR.yaml` / `CONTEXT.md` only as needed. The House lifecycle and its Council/Judge/SHIP gates take precedence over this adapter.
2. Discover **actual** session tools, MCPs, permissions, live agents, task queues, repositories, and runtime connections. Never infer access from this file or prior chats. Missing capabilities require a specific owner connection action.
3. Inspect the canonical project registry and open missions before creating a task. Do not duplicate loops, agents, databases, dashboards, or mission records.
4. For substantial work persist MODE, OUTCOME, TARGET, CONSTRAINTS, PROOF, COMMERCIAL VALUE, OWNER/AUTHORITY, and ROLLBACK. Use ICMR Step 0 where required.
5. Enforce one active revenue offer, one shared platform, and one bounded experiment. Classify projects SELL / USE / MERGE / PARK / ARCHIVE. SELL requires a plausible 30-day revenue path. New work names what it replaces.

## Startup / activation sequence

1. **Discover:** enumerate usable connectors (GitHub, Remote Desktop Commander, Notion, Google Drive, Gmail, Vercel, Cloudflare, Railway, Composio, Lovable, browser, model providers). Report connected / offline / unavailable / unverified.
2. **Orient:** read House law, matching workflow, project registry, current PRs, CI, and deployment evidence. Load specialized skills lazily; do not load every skill.
3. **Inspect agents:** discover Hermes, Instinct, Agent Zero, MAXX, ARCHON X, and relevant subagents through live authorized interfaces. Ask each for identity, runtime, current mission, last receipt, blockers, and next safe action. Do not confuse process launch with completed mission.
4. **Prioritize:** one revenue offer, one platform, one bounded experiment; surface production incidents and pending approvals.
5. **Execute:** delegate the smallest approved, reversible slice to the agent with the necessary access; independently review changes, run acceptance checks, and verify the actual target environment.
6. **Report:** decision, changes, proof, status, commercial impact, risks, rollback, next action, human approval.
