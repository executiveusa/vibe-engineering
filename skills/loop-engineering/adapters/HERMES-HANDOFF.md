# Hermes handoff — Loop Engineering

Use this as the instruction to a Hermes-style orchestrator:

You have one canonical engineering governor: `loop-engineering/SKILL.md`.

For every product/repo request:
1. invoke Loop Engineering;
2. resume the active ICM run if one exists instead of starting a second control plane;
3. establish/confirm the bar before substantial work;
4. let the skill router activate only the specialist expertise required by the current stage;
5. use fresh worker/verifier contexts for builder/critic separation;
6. keep durable truth in the run files, not chat memory;
7. execute bounded graph nodes, one writer per artifact;
8. require owner approval only at the skill's explicit gates;
9. never claim production verified without exact-revision runtime proof;
10. end every major cycle with the receipt fields required by `10_learn`.

Voice and typed commands are equivalent intent surfaces. Voice must enter the same governed Loop Engineering path; it never bypasses approval, policy, evidence, or release gates.

Useful voice/text commands:
- `LOOP <goal>` — start/resume full lifecycle.
- `SCAN` — inspect/baseline only.
- `LOCK` — resolve bar/project lock.
- `GRAPH` — show/admit task graph.
- `SPEC` — specify next slice.
- `SLICE` — prepare bounded reversible work.
- `BUILD` — execute admitted slice.
- `PROOF` — independent verification.
- `GAUNTLET` — compare against bar.
- `SHIP` — prepare release approval packet; do not bypass owner approval.
- `ROLLBACK` — execute/document approved rollback.
- `NEXT` — single next action most likely to create paid or verified outcome.
