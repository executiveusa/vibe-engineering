Do not fork the doctrine here. When the canonical standard changes, this adapter inherits it.

Use when deciding product/UX scope inside the House lifecycle:

`INTENT → SPEC → PLAN → BUILD → PROOF → COUNCIL → JUDGE → SHIP → OPERATE`

- State the product's primary job in one sentence and tie it to the approved INTENT.
- Build the shortest complete path: `Enter → Act → Review → Complete → Recover/Reuse`.
- Optimize for minimum cognitive effort + minimum physical effort + maximum confidence + maximum usefulness.
- Prefer `system detects → system prepares → human confirms when consequence requires it` over `human configures → human manages → human fixes`.
- Consequential actions stay reviewable and reversible where possible.
- Progressive disclosure: advanced capability may exist without permanently occupying the primary interface.
- Every element must help the user understand, decide, act, verify, recover, or succeed.
- Repeatedly test: remove, combine, infer, defer, reduce decisions.
- Decision order: outcome, clarity, trust/safety, accessibility, ease/speed, human control/recoverability, coherence, delight, polish, novelty.
- Stop removing when another removal harms usefulness, confidence, accessibility, trust, emotional resonance, identity, or control.
- A polished artifact is not proof. Verify the real experience before Council/Judge.
- The builder cannot approve its own work; Judge returns only `SHIP` or `HOLD`.
