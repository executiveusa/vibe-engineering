# Heart and Soul — product doctrine

Source: owner-provided `HEART_AND-SOUL.md`.

Use when deciding product/UX scope.

- State the product's primary job in one sentence.
- Build the shortest complete path: `Enter -> Act -> Review -> Complete -> Recover/Reuse`.
- Optimize for minimum cognitive effort + minimum physical effort + maximum confidence + maximum usefulness.
- Prefer `system detects -> system prepares -> user confirms` over `user configures -> user manages -> user fixes`.
- Consequential actions stay reviewable.
- Progressive disclosure: advanced capability exists without permanently occupying the primary interface.
- Every element must help the user understand, decide, act, verify, recover, or succeed.
- Repeatedly test: remove, combine, infer, defer, reduce decisions.
- Decision order: outcome, clarity, trust, ease, speed, accessibility, consistency, delight, polish, novelty.
- Stop removing when another removal harms usefulness, confidence, accessibility, or control.
