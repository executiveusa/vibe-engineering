# Collins-level rigor — web/product design doctrine

Source: owner-provided Collins-level website protocol. This is rigor, not visual imitation.

Use for website/product experience work.

1. Strategy before styling: customer, problem, outcome, positioning, content, proof, constraints, governing idea.
2. Self-evident before experimental. Surprise after comprehension, never instead of it.
3. Content before containers. Real content shapes hierarchy, typography, imagery, pacing, interaction.
4. Distinction before decoration. A site must express a defensible belief/difference, not generic premium polish.
5. Systems before isolated screens. Design across pages, breakpoints, states, content lengths, languages, future updates.
6. Proof before claims. Never call usable, accessible, responsive, fast, complete, or production-ready without evidence.
7. Mobile is intentionally designed, not a compressed desktop.
8. Builder cannot approve itself. Independent reviews cover customer value, usability, creative direction, accessibility, technical quality, and sovereignty.
9. For web release use the weighted score and hard floors in `_shared/standards/bar-and-gauntlet.md`.
